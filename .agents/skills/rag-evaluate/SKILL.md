# RAG evaluation

Follow repository `AGENTS.md` and read [RAG workflow recipes](../../../docs/learning/codex-workflows.md). Default to saved-evidence diagnosis and focused offline pytest; the invocation does not authorize paid calls, additional Message prompts, project revisions or source activation. Findings return to the approved implementation workflow.

1. Identify the requested evaluation: saved captures, offline regression, or approved live acceptance. Recover the approved manifest, source/configuration fingerprint and cumulative run budget. Older reports are historical until refreshed.
2. Diagnose the complete execution path: extraction/corpus identity, scope/authority, retrieval/rerank, drafting/verification/recovery, terminal outcome/persistence, Regular/SSE/GET and UI. Transport 200, citations, retrieval hits or schema normalization alone are not acceptance.
3. Inspect existing captures first. Preserve frozen inputs and hashes; normalize a copy with `python -m app.cli.acceptance_report` from backend when appropriate. Record case/repetition, request/message IDs, timings, status and actual response bodies. Source/legal labels need verified source evidence, not a previous generated answer.
4. For offline work, use repository venv and Windows adapter or equivalent Make targets. DB integration requires explicitly verified disposable test settings and `--allow-integration`; ordinary tests retain hash/noop/echo and external-HTTP guards. Do not run migrations, Docker or start provider-connected processes as an evaluation prerequisite without authorization.
5. Live runs require approval covering exact prompts/repetitions, environment, mutations and paid usage. Confirm effective immutable project configuration, active/candidate source/build identity and running code before dispatch. Use an isolated approved environment and existing `rag-journey` controls; paid runs require `--paid-eval --budget-usd <finite-positive-limit>` on every invocation. Each invocation currently generates a new run token. Before every dispatch, reserve its maximum provider cost and effect counts in the parent task ledger. Separate commands, repeats and comparisons share the approved cumulative allowance; unknown outcomes retain reservations. Reconcile actual supported costs afterward. The ledger records task authority; existing provider enforcement remains necessary and unaccounted providers must be explicitly bounded before dispatch. Cohere accounting does not cap other LLM/translation providers: identify and bound those separately or stop before dispatch. Leave live flags unchanged unless explicitly approved.
6. Browser acceptance stays with the exact owning authenticated tab/project. Use `$browser-qa`'s supported capability discovery and network capture where available. Parse actual fetch-stream SSE evidence; GET or screenshots do not substitute for streaming parity. A separate API replay requires its own authorization and must be labelled separately.
7. Run the approved final matrix only after diagnostic readiness; a smaller diagnostic subset does not replace it. Retain grounding, source restrictions, latency and transport/parity requirements. Never activate candidates, edit frozen captures, lower acceptance or repeat costly failures without new evidence.

Hand off commands/environment, current identity, passed/failed/blocked/unverified criteria, saved evidence paths and exact remaining gaps. Resume retains used counters and invalidates evidence whose source, configuration, dependencies or runtime changed.
